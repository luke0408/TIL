# 임베딩 벡터

## Summary

임베딩 벡터는 텍스트나 이미지 같은 입력을 고정 길이의 실수 벡터로 바꾼 것이다. 의미가 비슷한 입력은 벡터 공간에서 가까운 위치에 놓인다. 그래서 "의미가 비슷한가"라는 질문을 "벡터가 가까운가"라는 계산 문제로 바꿀 수 있다. 임베딩을 제대로 쓰려면 밀집 벡터의 성질, L2 정규화, 코사인 유사도를 함께 이해해야 한다.

이 노트는 스터디 토론 내용을 바탕으로 정리했다.

## Details

### 희소 벡터와 밀집 벡터

TF-IDF나 Bag-of-Words 같은 전통적인 표현은 희소 벡터다. 차원 수가 어휘 크기만큼 크고, 각 차원이 특정 단어 하나에 대응한다. 문서에 없는 단어의 차원은 모두 0이므로 값의 대부분이 0이다. 이 방식은 해석이 쉽지만, "자동차"와 "차량"처럼 단어가 다르면 의미가 같아도 겹치는 차원이 없다.

실무 임베딩 모델은 밀집 벡터를 만든다. 차원 수는 보통 384, 768, 1536처럼 수백에서 수천 개이고, 거의 모든 차원에 0이 아닌 값이 들어간다. 차원 하나가 특정 단어나 개념을 뜻하지 않는다. 의미는 여러 차원에 나뉘어 표현된다. 그래서 개별 차원을 사람이 해석할 수는 없지만, 단어가 달라도 의미가 비슷하면 가까운 벡터가 나온다.

| 구분 | 희소 벡터 | 밀집 벡터 |
| --- | --- | --- |
| 예 | TF-IDF, BM25, one-hot | Sentence-BERT, OpenAI 임베딩 |
| 차원 수 | 어휘 크기 (수만 이상) | 수백에서 수천 |
| 0이 아닌 값 | 아주 적음 | 거의 모든 차원 |
| 차원의 의미 | 단어 하나 | 의미가 여러 차원에 분산 |
| 강점 | 정확한 단어 일치 | 동의어, 바꿔 쓴 표현 |

### 유사도 지표와 L2 정규화

두 벡터의 가까움은 주로 세 지표로 잰다. 유클리드 거리(L2 거리)는 두 점 사이의 직선 거리다. 내적은 두 벡터의 성분 곱을 더한 값이다. 코사인 유사도는 내적을 두 벡터 길이의 곱으로 나눈 값이며, 두 벡터 사이 각도만 본다. 값은 -1에서 1 사이이고 1에 가까울수록 방향이 같다.

벡터의 길이에는 의미 외의 요소가 섞일 수 있다. 예를 들어 입력의 길이나 특정 토큰의 빈도가 벡터 크기에 영향을 준다. L2 정규화는 벡터를 자신의 길이로 나누어 길이를 1로 맞춘다. 정규화 후에는 크기 차이가 사라지고 방향만 남는다.

정규화한 벡터에서는 세 지표가 같은 순위를 만든다. 길이가 1이면 코사인 유사도는 내적과 같다. L2 거리의 제곱은 `2 - 2 × 코사인 유사도`가 된다. 그래서 많은 벡터 DB는 벡터를 미리 정규화하고 계산이 가장 싼 내적을 사용한다.

```python
import numpy as np

a = np.array([3.0, 4.0])
b = np.array([6.0, 8.0])  # a와 방향은 같고 길이만 2배

print(np.linalg.norm(a - b))  # 5.0 -> L2 거리로는 멀다

def normalize(v):
    return v / np.linalg.norm(v)

a_n, b_n = normalize(a), normalize(b)
cos = a_n @ b_n               # 정규화 후 내적 = 코사인 유사도
print(cos)                    # 1.0 -> 방향이 같다
print(np.linalg.norm(a_n - b_n) ** 2, 2 - 2 * cos)  # 0.0 0.0
```

위 예에서 `a`와 `b`는 길이만 다르고 방향은 같다. 정규화 전에는 L2 거리가 5로 멀게 나오지만, 정규화 후에는 코사인 유사도가 1이고 L2 거리도 0이 된다.

:::note

어떤 지표가 맞는지는 모델이 학습한 방식에 달려 있다. 모델 문서에서 권장 지표와 출력 벡터의 정규화 여부를 먼저 확인해야 한다.

:::

### 임베딩 모델의 학습 방식

임베딩 모델은 보통 대조 학습(contrastive learning)으로 학습한다. 기준 문장(앵커), 같은 의미의 문장(포지티브), 다른 의미의 문장(네거티브)을 묶는다. 학습은 앵커와 포지티브의 거리를 줄이고, 앵커와 네거티브의 거리를 늘리는 방향으로 진행된다. 같은 배치의 다른 샘플을 네거티브로 쓰거나, 비슷해 보이지만 답이 아닌 하드 네거티브를 넣어 구분 능력을 높이기도 한다.

이 학습 방식에서 중요한 점은 "가깝다"의 기준을 학습 데이터가 정한다는 것이다. 일반 웹 문서로 학습한 모델은 법률이나 의료처럼 전문 용어가 많은 도메인에서 품질이 떨어질 수 있다. 같은 이유로 서로 다른 모델이 만든 벡터는 차원 수가 같아도 비교할 수 없다.

RAG에서 텍스트가 벡터로 바뀌는 단계는 [RAG Embedding의 구조와 동작](./RAG/Embedding.md)에서 다룬다. 만든 벡터를 대량으로 빠르게 찾는 방법은 [벡터 DB 인덱싱](./RAG/vector_db_architecture_and_indexing_hnsw_ivf_pq.md)으로 이어진다.
